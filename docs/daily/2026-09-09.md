# 2026-09-09 학습 기록

## 오늘의 목표

Entity를 직접 받지 않고 Request DTO와 Response DTO를 사용하며, Validation으로 잘못된 입력을 거부한다.

## 구현한 파일

- `member/dto/MemberCreateRequest.java`
- `member/dto/MemberResponse.java`
- `common/error/ValidationErrorResponse.java`
- `common/error/GlobalExceptionHandler.java`
- `member/MemberController.java`
- `member/MemberControllerTest.java`
- `docs/api.md`

## 정상 테스트

```bash
./mvnw clean test
curl -i -X POST http://localhost:8080/members \
  -H "Content-Type: application/json" \
  -d '{"name":"홍길동","email":"hong@example.com"}'
```

## 실패 테스트
- 빈 이름
- 공백 이름
- 잘못된 이메일
- 중복 이메일
- 존재하지 않는 API 경로

## 오늘 배운점
- Controller는 요청의 입구이다.
- DTO는 외부 데이터의 경계를 만든다.
- 형식 검증은 DTO Validation이 담당하고, 중복 이메일처럼 데이터 조회가 필요한 규칙은 Service가 담당한다.
